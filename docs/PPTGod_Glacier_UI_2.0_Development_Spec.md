# PPTGod · Glacier UI 2.0
## 前端视觉设计与 AI 开发执行规范

> 版本 2.0 | 桌面优先、响应式适配 | 中文 AI 演示文稿创作平台

## 1. AI 开发总指令

你是一名资深 SaaS 产品设计师、交互设计师和 Next.js 前端工程师。请在 PPTGod 现有代码库中完成 Glacier UI 2.0 视觉重构。以用户选定的冰川白工作台效果图为主要视觉基准，结合风格画廊、创作工坊、编辑器、我的项目效果图。保持已有业务逻辑、路由、数据模型、生成流程、模板与导出能力，不得为了视觉重构删除现有功能或伪造成功状态。

先检查 README、package.json、路由、全局 CSS、现有组件、主题配置及接口；以实际代码为准确认功能边界。优先复用现有组件和依赖，新增依赖前说明必要性。以下尺寸、色值与动效是建议实施规范，并非从效果图精确取样。新增功能须先确认接口支持，否则明确标记为未实现，不得展示可操作的假功能。

## 2. 产品定位与设计哲学

PPTGod 是从资料、主题和灵感到可编辑演示文稿的 AI 创作平台，而非单纯模板商城。核心路径：输入主题或导入资料 → 解析与大纲 → 选择风格 → 生成 → 预览与修改 → 导出。

视觉语言：Glacier Glassmorphism + restrained Neumorphism + Bento Workspace。70% 极简实用、20% 冰川玻璃、10% AI 科技点缀。整体清透、专业、柔和、有空间层次。内容优先于装饰；模板可以有多种颜色，但应用外壳保持统一冰川白。禁止大面积霓虹、强发光、低对比灰字、厚重阴影、过多渐变、廉价卡通和全屏雪山壁纸。

## 4. 字体与图标

优先延续现有 Plus Jakarta Sans、Noto Sans SC；代码与参数使用 JetBrains Mono；衬线字体仅在特定幻灯片模板中使用。中文字体回退 PingFang SC、Microsoft YaHei、sans-serif。标题 30–34px/700，页面副标题 14–16px/400，模块标题 18–20px/600，正文 14px/400，辅助 12–13px，按钮 14px/600。行高正文 1.5–1.65。使用现有图标库（如 Lucide），线宽 1.75–2px，导航图标 20px，普通图标 16–18px；禁止 emoji 代替功能图标。Logo 采用冰蓝渐变 P 形标记，若尚无正式矢量资产，沿用现有 Logo，不擅自更换品牌。

## 5. 全局应用框架

桌面参考 1440×900，顶栏 64px，左栏 220px（可收起为 64px），主内容 padding 24px，模块 gap 16px。顶栏左侧品牌，中央一级功能导航，右侧全局搜索、通知、账户。侧栏：首页、新建演示、我的项目、风格画廊、提示词工作室、设计体检、演讲排练；底部帮助、反馈、设置。Pro 卡片仅在真实付费功能存在时展示。顶栏负责跨模块导航，侧栏负责工作区导航，避免重复入口过多；同一路由选中状态一致。内容区域独立滚动，编辑器模式可折叠全局侧栏以扩大画布。

建议 12 列 CSS Grid，主区域 min-width:0；常规页面最大内容宽度 1600px，编辑器不设固定最大宽度。所有幻灯片缩略图固定 aspect-ratio:16/9（实际文稿比例可切换），图片 object-fit:contain，禁止拉伸。导航、表单和按钮不得因长中文文案溢出。

## 6. 页面详细开发提示词

### 6.1 首页 Dashboard（首要视觉基准）

复现参考图的工作台结构。标题区显示“你好，开始用 AI 创作你的演示文稿吧”，仅 AI 创作使用蓝色强调；右上角淡冰川插画，背景不超过标题区域。

第一行：8:4 双栏。左侧 AI 创作面板含 AI 生成、资料转 PPT、从模板新建三个 Tab；多行主题输入框、页数、受众、语言、高级设置和蓝色生成按钮。右侧上传面板使用虚线边框、云上传图标、支持格式与选择文件。文件大小、格式限制从实际配置读取。两种入口共享生成状态，避免重复提交。

第二行：9:3。左侧“同一内容 · 不同风格效果对比”，三张真实 16:9 缩略图，分别展示商务专业、清新学术、创意科技，单选控件和简短适用场景。右侧推荐风格 2×3 网格，支持查看详情。风格名、数量及预览必须来自真实模板库，参考图中的内容仅为示例。

第三行：4:8。最近项目显示封面、名称、页数、更新时间及更多操作；快速工具四卡为创作工坊、设计体检、演讲排练、提示词工作室。没有项目时展示新建入口，不填充虚假记录。

### 6.2 风格画廊 Gallery

顶部标题“风格画廊”及一句说明，右侧淡山脉装饰。第一行场景分类胶囊：全部、学术科研、商务汇报、科技创新、教育培训等，以实际分类为准。第二行使用场景、视觉风格、配色筛选、关键词搜索、排序。主体桌面四列、平板两至三列、移动端一列。模板卡片包含 16:9 封面、风格名、标签、收藏及选中状态。悬停显示预览、使用风格，选中使用 2px 蓝色边框。详情 Drawer 展示真实页型缩略图、配色、字体、适用场景、使用及加入对比按钮。筛选状态可写入 URL，空结果提供清除筛选。

### 6.3 新建演示 / 创作工坊

采用四步流程：内容与资料 → 选择风格 → AI 生成 → 预览与优化。左侧步骤栏约 190px，中部输入区域和右侧实时预览约 60:40。输入区包括主题、补充要求、示例快捷项、拖拽上传和文件列表；每个文件展示名称、大小、解析状态、移除操作。上传错误逐文件提示。预览区显示 16:9 主画布及页型缩略图；无内容时标明“示例预览”，不能暗示已生成。下方横向风格选择区和固定操作栏，含页数、比例、语言、高级设置、开始生成。大纲确认可编辑章节标题、要点、页数、顺序。生成期间展示实际进度或不确定进度，不编造百分比；失败支持重试并保留输入。

### 6.4 演示编辑器 Editor

编辑器独立工作区：顶部文稿名、保存状态、撤销重做、演示、导出 PPTX；左栏 210–240px 幻灯片树和大纲切换；中间弹性画布，右栏 300–340px 属性面板与 AI 助手。顶部工具条包含比例、文本、图片、形状、图表、表格、素材、排版、主题等实际支持的能力。画布区域采用淡灰蓝背景，幻灯片保持原始比例与白色边框。底部页码、缩放、全屏和演讲备注。右侧设计面板展示页面设置、主题、配色、字体；AI 助手包含上下文、修改输入、建议预览和确认应用。仅支持预览的元素不得伪装为可编辑；如已有编辑引擎则复用。保存状态应区分保存中、已保存、失败。删除、覆盖和批量修改需确认或可撤销。

### 6.5 风格对比 Comparator

标题区提供统一主题、页型切换（封面、目录、内容、数据等真实支持页型）。桌面 2–3 列等宽对比，每张卡片包含同一内容的真实渲染、配色条、风格说明、使用按钮。切换页型同步更新所有预览；添加、替换、移除对比对象。移动端纵向堆叠或横向可滚动。不可将不同文案的封面当作同内容对比。

### 6.6 设计体检 Audit

左侧文稿页列表，中部问题页预览，右侧体检详情。顶部显示真实评分或检查完成状态；检查维度可包括对齐、留白、对比度、字号、文字密度、色彩一致性和溢出。问题分严重、建议、通过，显示具体页码和定位信息；点击定位画布。建议展示修改前后预览，用户确认后应用；不支持自动修复时仅提供可执行建议。评分须基于真实规则，不伪造 AI 分数。

### 6.7 演讲排练 Rehearsal

以演示者视图为中心，左侧当前幻灯片和下一页，右侧演讲备注、计时、进度和排练控制。开始、暂停、结束、重新排练具有明确状态。若已有语音分析能力，提供授权后录音、语速、停顿、时长与反馈；没有能力则不展示虚假分析。麦克风权限被拒绝时允许无录音计时。排练结果提供按页时间与改进建议，录音处理遵循现有隐私策略。

### 6.8 提示词工作室 Prompt Studio

左侧参数配置（场景、受众、视觉风格、色彩、字体、排版、页型、内容密度、限制条件），右侧实时编译提示词预览，底部复制、重置、保存及使用提示词。高级参数折叠；模板默认值与用户覆盖值区分。复制按钮有成功/失败反馈。复用现有 prompt compiler，不在 UI 中重复实现生成逻辑。

### 6.9 我的项目 Projects

标题区、淡山脉插画、新建按钮。可选统计卡：全部项目、最近编辑、收藏、共享（仅真实支持时）。筛选栏含搜索、分组、排序、网格/列表切换。桌面四列卡片，封面 16:9，标题最多两行，状态、标签、更新时间、收藏和更多菜单。操作包括打开、重命名、复制、删除、导出（以现有能力为准）。删除需确认；空项目展示创建入口。统计数据由真实项目集合计算。

### 6.10 设置、帮助与账户

使用统一 AppShell，设置采用分组表单和保存状态；帮助采用可搜索的 FAQ 或现有文档链接。账户与登录界面保持冰川色，输入框与错误提示遵循同一组件规范。不存在的会员、共享、通知服务不添加假入口。

## 7. 组件系统

| 组件 | 规范 |
|---|---|
| AppShell / Topbar / Sidebar | 统一布局、路由高亮、折叠、移动抽屉 |
| GlacierPanel | 16px 圆角、细边框、轻阴影；支持标题和操作槽 |
| PrimaryButton | 高 40–44px，蓝色，hover/active/focus/disabled/loading |
| SecondaryButton | 白底、蓝灰边框，不抢主操作 |
| IconButton | 36–40px，tooltip 和 aria-label |
| TextInput / Textarea | 40–44px 基础高度，错误文案、label、focus |
| Select / Tabs / FilterChip | 选中蓝底浅色，键盘可操作 |
| UploadDropzone | 拖拽、点击、进度、取消、错误及文件列表 |
| SlidePreview | 固定比例、真实渲染、加载和失败占位 |
| StyleCard | 封面、标题、标签、收藏、选择、预览 |
| ProjectCard | 项目元数据、状态、更多菜单 |

所有组件需覆盖默认、悬停、按下、选中、焦点、禁用、加载、错误状态。组件通过 props 与业务数据交互，避免在展示组件中硬编码接口。重复卡片由数据映射渲染。

## 8. 动效与视觉资产

hover 120–180ms，弹层 180–240ms，页面局部切换 200ms；使用 opacity/transform，卡片悬停最多上移 2px。AI 生成使用轻微流光或进度动画，禁止持续大面积粒子。尊重 prefers-reduced-motion。背景资产采用 SVG 或压缩 WebP/AVIF，提供静态回退；雪山只做局部背景。模板预览应来自实际渲染结果或已有模板资产，不使用整张 UI 效果图作为网页背景，不把界面文字烘焙进图片。

## 9. 响应式规则

- ≥1440px：完整侧栏，首页 8:4、9:3、4:8 网格；画廊四列。
- 1024–1439px：侧栏 200px 或可折叠；画廊三列，首页按空间调整。
- 768–1023px：侧栏收起，主区双列或单列；编辑器属性面板抽屉化。
- <768px：移动导航抽屉，主区单列，卡片 1–2 列，表单纵向，主按钮全宽；编辑器优先预览和基础操作，复杂编辑能力明确限制。

不得整体缩放桌面页面模拟移动端。验证 390、768、1024、1440、1920px 宽度，无非预期横向滚动。

## 10. 工程实施建议

以现有 Next.js/React/TypeScript 结构为准，以下仅为建议组织方式，不强制迁移路由：

```text
src/
  app/                 # 保留现有路由
  components/
    layout/            # AppShell, Sidebar, Topbar
    ui/                # Button, Panel, Input, Tabs, Dialog
    presentation/      # SlidePreview, StyleCard, EditorCanvas
    projects/          # ProjectCard, ProjectFilters
  styles/              # glacier tokens, global styles
  lib/                 # 复用现有解析、生成、导出逻辑
public/
  brand/               # Logo、冰川背景等
```

优先 CSS Variables 与现有 Tailwind/CSS 体系；禁止新增第二套互相冲突的 UI 框架。服务端组件用于静态内容，客户端组件用于交互（以现有框架版本为准）。保持 TypeScript 类型安全，避免 any；文件上传与 AI 请求复用现有接口，服务端校验输入，不将 API 密钥暴露到浏览器。不要修改与视觉重构无关的数据库、鉴权或部署配置。若功能需新增接口，单独列出契约与待办。

## 11. 可访问性、性能与异常状态

普通文本对比度至少 4.5:1，大文本至少 3:1；图标按钮提供可访问名称；所有表单有明确标签；Tab 顺序合理，弹窗管理焦点。状态不能只靠颜色表达。移动触控目标尽量 44px。图片懒加载，缩略图使用合适尺寸，避免全页 backdrop-filter 与过量阴影；列表较大时按需分页或虚拟化。错误提示说明原因及恢复方式；网络失败保留草稿；生成、上传、导出均需防重复提交。性能目标（生产环境测量）：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，以真实测量为准。
